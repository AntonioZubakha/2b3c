# Requirements: 2B3C (brownfield / Stonee monorepo)

**Defined:** 2026-05-14  
**Core value:** Два пути в каталоге (готовое / оправа+камни) + оплата + отслеживание изготовления/доставки — для рынка РФ, ориентир Rare Carat.

## v1 Requirements

### Product & catalog

- [ ] **CAT-01**: Покупатель видит и завершает покупку **готового украшения** (каталог → карточка → корзина/чекаут).
- [ ] **CAT-02**: Покупатель проходит сценарий **выбор украшения (оправа) → выбор камней**, совместимых с выбранной оправой, до корзины/чекаута.
- [ ] **CAT-03**: Оба сценария используют **согласованные** модели корзины/заказа и не ломают существующие API без миграции данных.

### Checkout, payment, order

- [ ] **ORD-01**: Оплата и подтверждение заказа работают для обоих сценариев (Stripe; путь под РФ — поэтапно, без регресса текущего happy-path).
- [ ] **ORD-02**: Статусы заказа отражают этапы **оплата → изготовление (если применимо) → доставка** там, где это уже заложено в домене; пробелы явно задокументированы в `info/` до реализации.

### Tracking & trust

- [ ] **TRK-01**: Покупатель может **отслеживать** заказ: доставка или изготовление+доставка (минимум — понятные статусы и подсказки в UI).
- [ ] **TRK-02**: Копирайт и подсказки не обещают то, чего нет в бэкенде (согласованность UI ↔ API).

### Brand & market

- [ ] **BRD-01**: Публичное имя **2B3C** отражено в ключевых пользовательских точках (шапка, title, письма/шаблоны — по мере готовности), без обязательного переименования npm-scope в v1.
- [ ] **BRD-02**: Контент и UX учитывают **РФ** (язык по умолчанию, форматы, юридические формулировки — в рамках текущей архитектуры i18n).

### Quality gate (репозиторий)

- [ ] **QLT-01**: `pnpm run test` (frontend Vitest) зелёный после изменений в затронутых областях.
- [ ] **QLT-02**: `pnpm run lint` зелёный для пакетов, где настроен lint.
- [ ] **QLT-03**: После изменений в gateway/сервисах — `pnpm run smoke` на поднятом `docker compose` (см. `info/DEVELOPMENT.md`).

## v2 (отложено)

- Полная смена бренда в npm (`@stonee/*` → новый scope), отдельные платёжные провайдеры РФ, расширенная аналитика конкурента.

## Out of scope

| Feature | Reason |
|---------|--------|
| Паритет функций Rare Carat | Ориентир по UX, не требование 1:1 |
| Переименование репозитория | Риск для CI/ссылок; отдельное решение |
