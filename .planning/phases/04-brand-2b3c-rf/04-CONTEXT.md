# Phase 4 — Контекст: бренд **2B3C** и локализация **РФ**

**Дата:** 2026-05-14  
**Зависимость:** Phase 3 (трекинг) — закрыта.  
**Требования:** BRD-01, BRD-02 (`REQUIREMENTS.md`).

## Роль бренда и голос

- **Публичное имя продукта (UX, маркетинг, SEO для витрины):** **2B3C** — коротко, без лишних пояснений в шапке; при необходимости lockup **«2B3C · ателье»** / **«2B3C — …»** в подзаголовках и meta, если так согласовано в ходе исполнения (см. `PROJECT.md`: рабочее имя 2B3C).
- **Тон:** премиальная витрина, прозрачность цены и процесса, без перегруза юридическими обещаниями в маркетинговых строках.
- **Что не меняем в этой фазе (явные границы):**
  - Имена **репозитория**, **npm-scope** `@stonee/*`, **имена пакетов**, **технические ключи** `localStorage` / `stonee_*` ролей, **пути API** вроде `/ingest/stonee-json`, **имена файлов ассетов** (`stonee_logo.png`) — без отдельного решения о ребрендинге инфраструктуры (`PROJECT.md` Out of scope).
  - Внутренние роли `stonee_admin` и т.д. — идентификаторы домена, не торговая марка в UI (подписи ролей в auth — продуктовый текст, его можно выровнять под **2B3C** там, где это «имя платформы», не трогая value enum).

## Где появляется **2B3C** vs **Stonee**

| Слой | Ожидание Phase 4 |
|------|------------------|
| Покупательская витрина (nav, footer, home, about, SEO title/description, cart/checkout copy где «имя магазина») | **2B3C** (или lockup) |
| `index.html` статические meta / title (до гидрации) | Согласованы с публичным именем |
| `Seo.tsx` (`og:site_name`, суффикс title) | Публичное имя **2B3C**, логика суффикса не должна ломаться, если в title уже нет подстроки `stonee` |
| Комментарии в коде, пути `public/assets/stonee_logo.png` | Могут оставаться **Stonee** как техническое/историческое имя до смены ассетов |
| Документация `info/*` про «репозиторий Stonee» | Остаётся корректной; продуктовые абзацы — по необходимости одна строка отсылки к **2B3C** (не цель массовой правки MASTER/BUSINESS в этой фазе) |

## РФ: объём и границы

- **Язык по умолчанию:** уже `ru` в `apps/frontend/src/i18n/config.ts` (`fallbackLng: 'ru'`, `initialLanguage` → `ru` при отсутствии сохранённой локали).
- **`document.documentElement.lang`:** выставляется из i18n при старте и смене языка — ок.
- **Статический `<html lang="…">` в `index.html`:** сейчас `en` — **пробел** относительно BRD-02 (первый paint / SEO до JS); целесообразно выровнять на `ru` при согласовании с исполнителем (зафиксировать в GAP/плане 04-02).
- **Форматы:** даты/валюта/разделители — в рамках существующих хелперов (`displayI18n` и т.д.); новые библиотеки не требуются без пробела в RESEARCH.
- **Юридические формулировки:** только обзор и чеклист в `info/PRODUCT.md`; тексты вроде страховки (EN checkout), спорные утверждения для РФ — **не выдавать за юридически выверенные** без review; при сомнении — **Deferred** в чеклисте с rationale (см. threat model в PLAN 04-02).
